**Note — 第 62 輪：六個 P2（Codex 重審，thorough tier）→ 修好，含一個我自己引入的迴歸**

六項全部成立，且**第六項是第 61 輪的修法自己造成的新缺陷**：替換的 token 進入 aside 流後被接在主流末尾，於是

```bash
X=$(TOOL='env curl'; printf x)
TOOL=wget
$TOOL y
```

裡 subshell 內的 `TOOL` 成了 literals map 的最終定義，F6b 回報 `env`／`curl`，而 bash 實際展開的是外層的 `wget`。**替換是 subshell，它的賦值不屬於外層 shell。** 已為 aside token 加上標記並在建 literals map 時排除。

其餘五項與一個共同形狀有關：**述詞依「拼字」而非「位置／語意」判斷**，於是在兩個方向上都錯。

| # | 缺陷 | 兩個方向 |
|---|------|----------|
| 1 | `expansion()` 只找 `$(` 與 `${`，不看引號也不認其他構造 | 漏掉會執行的（`${v:-`curl x`}`、`${v:-<(curl x)}`）；也回報**不會**執行的（`${v:-'$(curl x)'}` 是字面值、`${v:-$((n + 1))}` 的 `n` 是變數不是命令） |
| 2 | `closeBrace` 把每個 `{` 都當成巢狀展開 | `${v:-{}` 合法（`{` 就是預設值），卻被判為不平衡 |
| 3 | 替換內的 `case` 拒收比對任何拼作 `case` 的 token | `X=$(printf case)` 被誤拒；而**再加一個拼作 `esac` 的引數就會通過**——這正是「讀拼字不讀文法」的證明 |
| 4 | `REDIR` 缺 `>\|`；heredoc 拒收先於算術命令 | `>\| /dev/null curl x` 被拆成 `>` 加管線 `\|`，回報`null` 漏掉 `curl`；`(( 1 << 2 ))` 的左移被當成 heredoc 拒收 |
| 5 | `OPAQUE_FLAGS` 要求未加引號；`OPAQUE_WORDS` 對任何位置的字生效 | `find . "-exec" curl {} +` 執行 curl 但因為旗標加了引號而豁免；反向則是 `printf xargs` 的資料引數被誤拒。加引號不會改變程式收到的引數，所以旗標**不看引號**；而 `xargs`／`alias` 是**命令**，所以移到 descent 解出的命令位置上判斷 |

`case` 的判斷改由新的 `opensCase()` 決定：一個 token 位於命令位置，當且僅當它在該 segment 之前的全部 token 都是保留字。`ARR+=(curl)` 也補進陣列賦值拒收。

**十五個新控制，十二點突變驗證**。這輪再次驗證了記憶裡那條：第一次突變回合有四個回報「pass 0 / fail 1」，那不是抓到突變，是 shell 的 `\&\&` 逸出把檔案改壞了——**壞掉的檔案與「測試沒發現」外觀完全相同**。改用 JSON 突變規格檔重跑，並讓腳本區分 CAUGHT／SURVIVED／BROKEN FILE 三種結果，十二點全數 CAUGHT。我斷言為合法的九個形狀先用 `bash -n` 驗過才寫進測試。全套件 3381 / 3375 pass / 0 fail / 6 skipped。

**Note — 第 63 輪：四個 P2（Codex 重審，thorough tier）→ 又一次是自己的修法造成的**

第 62 輪的兩處修法各自產生一個新缺陷，這是**連續第三輪**出現同一形狀：

| 缺陷 | 來自 | 說明 |
|------|------|------|
| `${v:-$(( $(curl x) + 1 ))}` 什麼都不回報 | 第 62 輪「算術產出的是數字，跳過整段」 | 跳過是對的方向、錯的力道：算術裡寫的替換 bash **仍然會執行**。跳過之前（把 `$((` 誤當 `$(`）至少還抽得到 curl，跳過之後直接不見——比它取代的缺陷更糟 |
| `${v:-$(printf })}` 被判為不平衡 | 第 62 輪 closeBrace 改成由 `${` 決定巢狀 | 只跳過 `${…}` 與引號，沒跳過 `$( … )`，於是當成引數傳入的 `}` 關掉了外層展開 |
| `$(cat <<< case)` 被誤拒 | 第 63 輪新增的 `opensCase()` | 每個運算子都重設「命令位置」旗標，包括重導向——但重導向的運算元不是命令位置 |
| `printf '%s' "-exec"` 被誤拒；`/usr/bin/xargs curl` 被放行 | 第 62 輪把旗標改成不看引號、把字詞述詞移到命令位置 | 旗標移得不夠遠（仍對任何 token 生效，而 `-exec` 只有作為 `find` 的運算元才是構造）；字詞述詞留了 `!qualified` 例外，於是寫出完整路徑就能繞過一道**強制**拒收 |

**這三輪連續的規律，值得寫下來**：每一輪我修好一個述詞，同一輪就在它旁邊種下一個。共同成因不是粗心，是**述詞的作用域比它的語意寬**——`-exec` 的語意是「`find` 的運算元」，卻寫成「任何 token」；`xargs` 的語意是「命令」，卻加了「未加路徑」這個與語意無關的條件；算術的語意是「產出數字」，卻寫成「整段不看」。修法一律是把述詞綁回它真正的位置，而不是加條件。

第 63 輪起，Codex 的複審提示改成明確要求「**先做迴歸掃描**」：連續三輪都是自己的修法弄壞既有行為，那就不該把它當成順帶檢查的項目。

七個新配對控制，五個決策點突變驗證（全數 CAUGHT，且先確認替換已套用）。全套件 3381 / 3375 pass / 0 fail / 6 skipped。

**Note — 第 64 輪：兩個 P2（Codex 重審，thorough tier）→ 四輪來第一次沒有迴歸**

Codex 明確回報「找不到任何本輪之前會觸發、現在不觸發的檢查」——連續三輪自傷之後的第一次。兩項發現都成立：

1. **`-exec` 的作用域還差一層**。第 63 輪把旗標從「任何 token」收到「`find` 的運算元」，但 `find /dev/null -name -exec` 裡的 `-exec` 是 `-name` 吃掉的**樣式**，不是動作。這與 `sed -n 1p '-exec'` 是同一個錯誤、只是小一個尺度。改法是給 find 的運算元加上 arity（`FIND_ARG`／`FIND_NOARG`），未知的選項一律拒收而非猜過去——與 `WRAPPERS` 同一個契約。

2. **兩個新控制沒有釘住它們所描述的分支**。這一項比第一項更值得記：
   - 算術拒收的正則寫成 `` /`|\$\(/ ``，但只有 `$(` 那一支有控制。把 `` ` `` 拿掉全套件仍綠——因為既有的 backtick 測試打的是**頂層** handler，而 `${…}` 內的 `$((` 是被整段跳過的，通用 backtick 斷言根本看不到裡面。
   - `closeBrace` 跳過 `$(`／`<(`／`>(` 三支，但控制只有 `$(` 那支；`${v:-<(curl)}` 的既有測試裡沒有 `}`，所以拿掉 `<(` 那支仍然全綠。

**這是一種與「缺陷」不同的東西：oracle 的解析度低於實作的解析度。** 一個決策若由多個 alternative 組成，只測其中一支，那條斷言證明的是「這個決策有被用到」，不是「每一支都還在」。我的十二點突變驗證全數 CAUGHT，卻沒發現這件事——因為我突變的是**整個決策**（把整行拿掉），而不是它的**單一分支**。突變的粒度必須對齊實作的粒度，否則綠燈只說明「這段程式有人在用」。

同輪也再次驗證了粒度的價值：新增的六點突變裡 `FIND_NOARG` 一項**存活**（SURVIVED），因為當時沒有任何控制用到不吃運算元的 predicate。補上 `find . -type f -print` 之後轉為 CAUGHT。這是本輪唯一一個靠突變（而非靠 Codex、也非靠讀程式碼）發現的缺口。

**Note — 第 65 輪：兩個 P2（Codex 重審，thorough tier）→ 一個真正的繞道**

第一項是這幾輪最嚴重的一個，儘管同樣標 P2：`$VAR` 只在「往命令位置剝除」的迴圈裡被解析，於是所有**運算元**的走訪器（find 的 arity、`sh -c` 掃描、wrapper 選項）讀到的都是未解析的字。

```bash
ACT=-exec; find /dev/null $ACT curl {} +      # F6b 只回報 find
MODE=-c;   bash $MODE "printf hidden"          # 只回報 bash
OPT=-u;    env $OPT X curl y                   # 只回報 env
```

三者都是**已授權的外層命令藏著一個未授權的命令**——這正是 F6b 存在的理由，而不只是「少報一個相依」。改法是在命令解出之後、走訪器之前，對其餘的字做一次解析。

**同時要決定的是相反方向**：沒有字面值在視野內的 `$VAR`，在**引數**位置該不該拒收？命令位置的規則是「解析不出來就大聲拒收」，但引數位置照搬會直接拒掉 shipped fence 裡的 `rm -f "$MSG_FILE"`。我選擇放行，理由是引數位置的 `$VAR` 是 F6b 讀不到的**資料**，不是命令位置；並把這個判斷連同理由寫進第 66 輪的複審提示，請 Codex 直接反駁而不是由我假設。

第二項仍是 oracle 解析度：`-execdir` 拿掉、`-iname` 的 arity 從 1 改成 2，兩個突變都存活。後者尤其值得看——arity 宣告成 2 會**跨過**其後真正的 `-exec`，是一個「表格數字寫錯就靜默漏報」的形狀。兩者都補上了區辨控制。

四點突變全數 CAUGHT（含 Codex 指名的那兩個）。全套件 3381 / 3375 pass / 0 fail / 6 skipped。

**Note — 第 66／67 輪：三 + 四個 P2（Codex 重審，thorough tier）→ 引號語意、fail-open 政策、與一次自傷的檔案損毀**

第 66 輪三項、第 67 輪四項，全部成立。可以合併成三條線：

**(1) `quoted` 不等於「展開被抑制」。** 我把 tokenizer 的 `quoted` 旗標當成「這個字不會被展開」，但 bash 的雙引號抑制的是 word splitting 與 globbing，**不是展開**。於是第 65 輪關掉的繞道，換成雙引號寫法就整個開回來：`find /dev/null "$ACT"`、`bash "$MODE"`、`env "$OPT"` 三者都照舊執行。新增獨立的 `nx`（expansion suppressed）旗標，只有單引號與反斜線會設定它。第 67 輪又補上同一個掃描器的兩個反向缺陷：雙引號內的 `\$` 沒設 `nx`（`"\$ACT"` 被誤解析），雙引號內的 `${ACT}` 根本沒被寫進字（走訪器收到空引數）。

**(2) fail-open 的邊界。** 我原本讓「視野內沒有字面值的 `$VAR`」在引數位置一律放行，理由是拒收會擋掉 shipped fence 的 `rm -f "$MSG_FILE"`。Codex 的反駁成立且關鍵：**放行只有在最壞情況是「資料」時才站得住**；在會決定「跑什麼」的運算元上，最壞情況是命令。`bash "$MODE" "printf hidden"` 在 fence 內沒有任何賦值時通過 F6b，而繼承來的 `MODE=-c` 就會執行隱藏的程式。現在三個「選擇命令」的走訪器（find 運算式、shell 選項、wrapper 選項）拒收；一般檔案運算元維持不透明。

我接著給的邊界「整個字必須就是那個展開」也被推翻——`bash "-$C"` 用前綴加展開組出 `-c`，`bash ${MODE:--c}` 是整字展開但簡單名稱正則認不得。改為：解析器**替換字裡的每一個展開**，替換後仍留有 `$` 的字才叫讀不懂，而讀不懂的字在那三個走訪器一律拒收。

**這個政策改變讓一處 shipped fence 變得有歧義**：`bash "$REPO_ROOT/scripts/run-skill.sh"`。我實測 bash 會拒絕 `-c/dev/null`（`invalid option`），所以那個字實際上塞不進 `-c`——但與其教 F6b 讀懂 bash 的短選項綑綁規則，我改的是 fence：加上 `--`，把它本來的意思寫出來。這是決策第 62 條（收窄輸入而非增強剖析器）第二次真正付出代價，而這次的代價是**一處 shipped fence 變得更明確**，不是變得更難寫。

**(3) oracle 的解析度，第三次。** `FIND_ARG` 的 arity 由 loop 自己生成運算元，所以 loop 無法反駁它自己（`-ipath` 1→2 存活）；補上獨立的一行 `opt === '-fprintf' ? 2 : 1` 之後才抓得到。接著 Codex 指出**成員資格**同樣沒被釘住——刪掉 `-ipath` 或 `-true`，連同它們的 oracle 一起消失。現在兩張表的鍵集合各再獨立宣告一次。這與「刪掉斷言不可能被抓到」不同：消失的是**剖析器支援的一個分支**，不是測試自己。

**方法上的事故，記在這裡因為它影響對這幾輪 diff 的信任度**：同一天有兩次我用 `String.replace` 套用多處替換，而 replacement 字串會解讀 `` $` ``（比對前的全文）與 `$'`（比對後的全文）。測試檔被靜默地複製成八份、共 98 個 test，`node --test` 只回報一行 `not ok 1`。重建後已驗證：49 個 test、每個一份、`node --check` 通過、全套件 3381 / 3375 pass / 0 fail / 6 skipped、`git diff --check` 乾淨。這件事連同前一次 `\&\&` 被 shell 吃掉的事故，寫成 lessons L4——**共同的偵測訊號是「`# tests` 的數字不等於已知的案例數」，那代表檔案壞了，不是測試失敗**。

**Note — 第 68 輪：四個 P2（Codex 重審，thorough tier）→ 其中兩個是我自己種的誤報**

Codex 同時確認了兩件事：`bash -- …` 的 fence 修改正確（它在 `/bin/bash` 底下實際執行過完整的 shipped fence），以及第 67 輪那次檔案重建是乾淨的（49 個 test 定義、每個抽取函式各一份、`node --check` 通過）。

四項發現全部成立，而**其中兩項是第 67 輪解析器新種下的誤報**：

1. `${MODE:--c}` 的前綴 `${MODE` 被當成完整展開替換掉——如果 `MODE` 有字面值，替換會把「這個字讀不懂」的**證據本身**（那個 `$`）抹掉。正則改成只匹配完整的 `$NAME` 或 `${NAME}` 兩種 alternative。
2. 解析後的值一律按空白切分。這對 `$VAR` 是對的，對 `"$VAR"` 正好相反——`CMD="/usr/bin/printf hidden"; env "$CMD"` 傳的是一個含空白的檔名，bash 找不到、什麼都不跑，F6b 卻報告了 printf。

另外兩項是漏網：被 arity 跳過的運算元從未被檢視（三個位置都補上 `consumed()`），以及頂層 `\$NAME` 分支根本沒有 oracle。

**誤報與漏報同等重要**，這一輪之後我把它寫進給 Codex 的固定要求：一個會為「從來不會執行的命令」要求授權的檢查，跟一個放行未授權命令的檢查，都是壞的檢查。

**Note — 第 69 輪：四個 P2（Codex 重審，thorough tier）→ 引號是「片段」層級的，以及一個我不同意的發現**

前三項成立且已修：

1. **`quoted` 是每個字一個旗標，但 bash 的引號是每個片段一個。** `env $CMD""` 裡那個空的引號片段讓整個字被判為「不會切分」，第 68 輪剛關上的繞道就在一個字元之外重新打開。實測 `[/usr/bin/curl][x]` 確實切成兩個字、確實跑了 curl。新增 `bare` 旗標（有片段寫在引號外），`oneWord = quoted && !bare` 回答「會不會切分」，`quoted` 繼續回答「字裡有沒有引號」——後者才是命令名稱那道拒收要問的。

2. **命令位置的解析器沒有套用同一組語意。** Codex 指出 `'$TOOL' x` 會被解析成 curl（bash 其實是找不到名為 `$TOOL` 的檔案），`"$TOOL"` 會被切分（bash 傳的是一個含空白的檔名）。**但直覺的修法——拒收所有帶引號的命令名稱——是錯的**：`TOOL=curl; "$TOOL" x` 真的會跑 curl（實測 `[curl][x]`），拒收等於用一個誤報換一個漏報。正確的修法是讓這個分支跟引數解析器問同樣的兩個問題：`nx` 決定要不要展開，`oneWord` 決定要不要切分。

3. **從字面值裡「跑出來」的 `$` 不是第二次展開。** bash 不會重新展開展開的結果：`CMD='$NOPE'; env "$CMD"` 是叫 env 執行一個名為 `$NOPE` 的檔案，什麼都不跑。原本的判斷看的是**替換後**的字串裡還有沒有 `$`，改成看**原始字串扣掉已解析區段後的殘餘**——留下來的才是 bash 還會動作的語法。

第四項（`timeout "$DURATION" /usr/bin/true` 被拒收）**我不同意，已附反例送回複審**：引號保證的是「一個字」，不是「這個字是 duration 而不是選項」。單一個字可以是綑綁形式的、會吃掉下一個字的選項——實測 `env -uFOO ./argv.sh a b` 可執行。套到 timeout：`timeout "$O" git curl x` 若 `O=-k5`，duration 是 `git`、命令是 `curl`，F6b 會報告已授權的 `git` 而 bash 跑的是未授權的 `curl`——正是第 65 輪關掉的那一類繞道。這台機器沒有 `timeout` binary，`-k5` 綑綁這個前提來自 coreutils 文件而非實測，這一點已如實寫給 Codex。

**方法上，這一輪有兩個我自己的突變存活，而它們各自帶出一個真的改動**：
- 我為第 2 點寫的控制用的是 `'$TOOL'`（單引號），它釘住的其實是 `nx` 而不是 `quoted`——正是這個存活讓我去檢查 `"$TOOL"`，才發現「拒收所有帶引號命令名稱」會造成漏報。**控制沒釘到它宣稱要釘的那個條件，比沒有控制更危險，因為它看起來已經釘住了。**
- 三個加在 `HOLE` 佔位符上的 `bare = true` 是**無效賦值**：佔位符裡沒有 `$`，沒有任何輸入能區分有沒有它。與其留著一個 oracle 無法變動的條件，不如刪掉——這是第 64 輪「oracle 解析度」那條規律的反向應用：不可釘住的條件不該存在。

十一個突變點，全部確認已套用且全數 CAUGHT。全套件 3381 / 3375 pass / 0 fail / 6 skipped；檔案 49 個 test、無重複；`git diff --check` 乾淨。

**Note — 第 70 輪：三個 P2（Codex 重審，thorough tier）→ 三個發現，一個成因；答案是收窄輸入而不是建模**

三項發現我都先在 `/bin/bash` 底下重現過才動手，包括那個保留的空欄位：

| 形狀 | bash 實際行為 | F6b 原本的答案 |

**成因只有一個：bash 的引號屬於「片段」，而這裡每個旗標都屬於「字」。** 一個字裡可以同時有被抑制的展開與作用中的展開、被引號保護的展開與會切分的展開，一個布林值說不出是哪一個。

**這一次我沒有再把剖析器做大。** 前面已經有兩輪的代價寫在決策第 62 條上（收窄輸入而非增強剖析器），這裡正是它該被套用的地方：新增 `act` 旗標（這個字裡有 bash 會執行的展開——這才是走訪器真正在問的問題，`text.includes('$')` 一直只是它的代理），然後把「片段引號不一致又含展開」的字**具名拒收**，位置在字進入 segment 的時候，早於解析器、走訪器與命令名稱檢查。四個形狀全部落在這道拒收裡。

賦值語句是例外，因為 **bash 不對賦值的值做 word splitting**，哪個片段帶引號不可能改變字數。這個例外由控制釘住，不是假設。

**Codex 的發現把我帶到同一類的相鄰繞道，一併修掉。** 讓賦值例外浮現的那個失敗控制，使我去看 `literals` 是怎麼建起來的——它存的是賦值的**原始文字**，但 bash 是**在賦值當下**展開的。`X=curl; TOOL="env $X"; $TOOL y` 存的是 `env $X`，變數裡實際是 `env curl`（實測真的會叫用 curl）。這是第 65 輪那個繞道再往前一個間接層。這樣的名稱不再被當成字面值記錄，解析它會被具名拒收。

| 3 | P2 | 外部 `time` 是 wrapper | `command time /usr/bin/printf` 兩個 binary 都跑 | 只報 `time`，operand 掉了 |
| 3 | P2 | command word 巢狀語意不一致 | `exec builtin X` / `command builtin X` / `exec exec X` 都打不到 X | 卻報了 `printf` |
| 4 | P2 | `name() { … }` 被當成外部命令 | `type -t git` 是 `function`，外部 git 從未執行 | 釘住 `['git','printf']`——**期望本身是錯的** |
| 4 | P2 | glob 拒收忽略引號 | `"/bin/e[c]ho"` 不展開，是字面檔名 | 誤拒 |
| 5 | P2 | 多個表格條目沒有任何輸入能變動 | — | 刪掉六條後套件仍全綠 |
| 6 | P2 | `TMPDIR` 可被 `mktemp` 讀成選項 | `TMPDIR=-d` → `invalid option -- /` | 未加 `--` |

**第 4 項是這輪的教訓。** 第 74 輪拒收了 `function name { … }`，然後在註解裡把 `name() { … }` 指定為「支援的寫法」，理由是「遮蔽只會**多**報被遮蔽的命令，不會藏起任何命令」。兩個半句都錯，而且第二半句正是 exact-set gate **fail open**：把真正的 `git` 呼叫換成一個叫 `git` 的 function，`exactSet()` 和 `agree()` 全綠，而真實外部集合已經**少了** git。**一輪修正在關掉一條漏洞的同時，用註解為它旁邊那條開了門。** 兩種寫法現在都拒收。

**第 2 項是第 74 輪 headline 換皮重演。** 第 74 輪的教訓是「oracle 從未斷言它宣稱的不變量」，我照著修了三個 oracle——然後在其中一個裡把**列舉器和驗證器寫成同一條 regex**。認不出來的站點不是「失敗」，是「消失」，而 `every()` 對剩下的仍為真。現在兩半分開，列舉器刻意寫得更笨（只要一行同時提到 `/bin/bash` 和 `$GUARD` 就是站點），驗證是結構性的。

**兩個 SURVIVED 的變異點各自帶出一條通則**，都在本輪一併移除：

- `assert.equal(x, 4)` 這種**常數斷言**，在正確的倉庫上沒有任何輸入能讓它變動——它必然 survive。它想保護的東西已由列舉器的變異點涵蓋，於是刪掉。
- 正向的 `assert.match(src, /…/)`**放寬永遠不會失敗**。要釘住它，必須把 matcher 具名、再餵一份刻意變異的來源要求它拒絕。

**shipped artifact 這輪也真的變強了**：`mktemp` 與六處 `rm -f` 全部補上 `--`。`TMPDIR` 是繼承來的輸入而且展開就在 template 最前面，實測 `TMPDIR=-d` 會讓系統 `mktemp` 讀成選項。

`BUILTINS` 是**唯一不適用「刪掉沒釘住的條目」的地方**——第 74 輪自己證明過：清單不完整不會 fail safe，它會**發明**一個依賴（`shopt` 就變成了幽靈相依）。為了滿足覆蓋率而刪 `bind` 只是換個名字把同一個缺陷放回去。改成從 `compgen -b` **推導**，一條控制涵蓋全部條目。

**`hash -p` 是這輪最該記的形狀**：它把名字重新綁到任意路徑，於是「F6b 報出的集合完全不變，而實際執行的東西變了」。exact-set oracle 在結構上就看不見這一類——它比較的是名字，而 `hash` 改的是名字到檔案的映射。
