## Background

The review state machine mirrors the world by **observing events**: every Edit/Write must be seen and classified, every verdict must be parsed out of tool output, and the state file must be kept in sync through locks, epochs, sidecar markers, and recovery paths. Each unobservable event becomes a silent desync, and each desync has historically been patched with more state.

Three incidents on 2026-08-11, one session, all with gates genuinely passed at the behaviour layer:

| Incident | Mechanism | Class |
|----------|-----------|-------|
| Full-mode precommit output (31–35KB) exceeded the harness ~30KB inline threshold; the tool result carried only a 2KB preview, `## Overall: ✅ PASS` was in the persisted file, hook fail-closed | Consumer-side stdout parsing | Verdict lost to truncation |
| Hand-composed `codex-reply` prompts lacked the literal `Merge Gate` / `Document Review` provenance phrase; five passing rounds were skipped (not inverted) | Request-side provenance regex | Verdict lost to paraphrase |
| A `.md` written **outside the repo** (session memory file) re-opened the doc gate: `hooks/post-edit-format.sh:1463` classifies by extension only (`grep -Eq '\.(md\|mdx)$'`), no repo containment | Edit observation over-triggers | Gate falsely re-opened |

A backgrounded precommit additionally has **no** recovery path (`background_reviews` markers cover the doc/code planes only), so its late verdict is unrecordable by design.

The structural diagnosis: the state file is a cache of derived facts maintained through observation, and observation keeps losing. The question the Stop gate actually needs answered — *does the current working tree have a passing verdict?* — is derivable at check time and needs no event history at all.

## Requirements

- Gate state is **derived at check time**, never maintained through edit observation — two separately-defined questions: *obligation* (a plane owes its gate iff its dirty set is non-empty; a clean checkout owes nothing) and *validity* (the owed gate is closed iff the newest **verdict** record for the plane's current digest is a pass, `mode_ok` holds, and no unresolved tombstone stands against that pair)
- Verdicts are **producer-emitted records** keyed to a content digest — an append-only log, not a mutable state machine. **Review verdicts bind to the digest captured at dispatch and revalidated at completion** (equal digests at both endpoints; the mid-window flap residual is documented, spec § 3.4) via **session-scoped transcript pairing with eager id-binding and at-most-once completion consumption** — dispatch records are **immutable and call-level** (one per tool call, carrying every plane the request opens) with all state transitions as append-only lifecycle events; position is only a bootstrap: binding is decided **per dispatch under the receipt lock** (a session-scoped **activation barrier** makes "this call's own entry" decidable — nothing below `activated_at` is ever capture-time bound; a call whose entry is already visible at capture binds on the dispatch line itself — one crash-atomic record; otherwise a lock-captured `frontier_start` opens a claim window closed by `frontier_end` on the terminal event; accounting is brought current before any bind; an unaccountable orphan poisons the dispatch `ambiguous`; a PreToolUse that cannot durably append its dispatch **blocks the tool call with `exit 2`**, the hook contract's one blocking status; concurrent same-key twins fold contested at read time even when the crash swallowed their contested events), and universal disposition gives every same-key transcript entry a durable `bound` or `quarantined` record, so candidate isolation survives cursor loss and record drops by accounting (transcript wall clocks are never consulted; aged dispositions fold into durable `frontier` records keyed to the transcript's file identity), and concurrent same-key calls are **contested and refused** with absolute precedence; consumption is ONE crash-atomic **settlement** record whose per-plane `plane_results` settle only on that plane's own recognition (dual-namespace outputs stay refused; a sentinel absent for a plane never mints that plane's receipt); the transcript is the only review-verdict path, and a completion that cannot be unambiguously paired is refused, never bound by fallback; foreground and backgrounded MCP calls land through the same cursor-incremental pairing sweep (offset + pending set), with a stop-guard final sweep — a check-time **writer** — before gates are derived; the runner refuses a PASS receipt on an **endpoint digest mismatch** between its validation baseline and `overallPass` (persistent drift caught; the exact endpoint-ABA flap is the documented residual)
- Record selection is the **newest verdict-bearing record for `(plane, current digest)`** — a runner verdict row or a settlement's `plane_results` projection; `"no-verdict"` entries, dispatch/event and tombstone records never participate in selection: edits invalidate implicitly (the digest drifts), late/backgrounded verdicts validate implicitly (their dispatch digest still matches), and a newer fail on identical content supersedes an older pass. Precommit records carry `mode` and the validity check honours `PRECOMMIT_REQUIRE_FULL`
- **Runtime evidence lives outside the repo directory** (user-set constraint): the verdict log goes in a per-repo local cache under the user's home (`${XDG_CACHE_HOME:-$HOME/.cache}/sd0x-dev-flow/receipts/<repo-slug>/`), so this change adds **zero new** repository-local runtime artifacts and nothing new needs a `.gitignore` entry (pre-existing runtime artifacts are the spec ❓ Q5 follow-up)
- The trust model is unchanged: cooperative threat model; records are producer-emitted, not cryptographically signed — the preserved property is *resistance to accidental minting*: precommit sheds output parsing in two steps (runner append now; the Bash **and Skill** verdict-parsing routes — the Skill route is a live receipt producer today, `post-tool-review-state.sh:3818–3903` — retire only once the runner absorbs the ecosystem fallbacks, spec WB2b), the end-state output-parsing path (MCP review recognition) is a guarded receipt producer with unchanged recognition rules, and prose/`cat`/truncated output still mint nothing
- Event-driven invalidation machinery (plane flags, edit epochs, dispatch-epoch retirement, background-review markers, lock-contention sidecars for the gate-state path) is retired in phases as the digest path proves out
- The round/stall progress ledger is **orthogonal and out of scope**: it tracks review convergence, not gate state, and is untouched by this change

## Acceptance Criteria

- [x] Per-plane digests are deterministic and **repo-contained by construction**: a write outside the repo root cannot change any digest (regression for the memory-file incident); unit tests cover ordering, tracked-modified, nested-untracked, deleted, renamed files (union classification — a cross-plane rename owes both planes), CRLF content, unstaged mode changes, and submodules (clean-at-index / moved / dirty-inside → `partial`)
- [x] `precommit-runner.js` writes its verdict record at the moment `overallPass` is computed; a truncated, piped, or backgrounded stdout has **no effect** on recording (regression for the 30KB incident: an output >30KB still lands its verdict); an **endpoint digest mismatch** between the post-`lint:fix` validation baseline and `overallPass` refuses the PASS receipt (drift that persists to completion is caught; the exact endpoint-ABA flap is the spec § 3.4 / ❓ Q6 documented residual); after WB2b, a non-Node repo's ecosystem checks run as runner steps and land their receipt through the same append — behaviour parity with today's Skill-route producer, which stays recognized until WB2b lands
- [x] A verdict arriving after its Bash call was backgrounded validates iff the recomputed digest matches — no marker/recovery machinery involved (regression for the unrecoverable backgrounded precommit)
- [x] The verdict log lives at the spec § 3.3 location outside the repo directory (relative `XDG_CACHE_HOME` rejected — resolved path verified outside the repo root); this change adds **zero new** repository-local runtime artifacts. **Check-time** unavailability of the cache fails closed: no readable log ⇒ owed gates open, loud error. The append-time double-write failure (primary log + tombstone fallback both unwritable) is the spec § 4 documented accepted residual; an unresolved tombstone unconditionally blocks its `(plane, digest)` until a primary PASS explicitly `resolves` it — no cross-file clock comparison — and the `$TMPDIR` fallback obeys the same containment rules as the primary cache, both pinned by tests
- [x] The review dispatch path writes digest-keyed records through the **single transcript-pairing writer with eager id-binding and at-most-once completion consumption** — concurrent byte-identical twin dispatches are **contested and every completion refused** (including the reversed-lock-order permutation with equal counts; contested precedence survives any later event), while sequential same-key dispatches bind eagerly and settle by tooluse_id; one call opening both planes settles via ONE crash-atomic settlement record whose `plane_results` carry a verdict only for the plane whose own recognition succeeded (the other plane settles `"no-verdict"`; a dual-namespace output settles every plane `"no-verdict"` — no cross-plane minting); a crash at any bind/settle boundary leaves either nothing spent or everything settled; a genuine identity with no valid sentinel settles all-no-verdict — an **attempt record, not evidence**: the identity is spent, selection ignores it, so the gate is open when the digest has no verdict and stays closed when an earlier same-digest PASS stands (a FAIL is what supersedes); a replayed or duplicate delivery pairs to a spent identity and is refused; a bound expired dispatch's late result is refused by name and a never-bound entry is quarantined as unaccounted — disposition accounting, never transcript clocks — with a >48h record drop shifting no survivor's binding — including a derived-contest member dropped at an asymmetric cutoff, whose surviving twin's `contested` acknowledgment is materialized write-ahead before the drop; a background handoff with zero or multiple candidates marks none; a task-owned dispatch pairs only with its own task's completion; a prose or `cat`-forged sentinel still mints nothing (negative controls in both directions per `@rules/testing.md` § Conventions, Guards row)
- [x] `stop-guard.sh` derives obligations from dirty sets and receipt validity by digest comparison: no read of `has_code_change` / `has_doc_change` / edit epochs on the gate-state path; `mode_ok` preserves `PRECOMMIT_REQUIRE_FULL`; a newer same-digest fail supersedes an older pass; dual-mode aggregate precedence and the residual-state validator (`review_mode`/`aggregate_gate`/plan fields) are unchanged; an edit between verdict and check opens the gate with zero hook involvement at edit time, and gates stay closed across out-of-repo writes, `git commit` of an unchanged tree, and session restarts
- [x] Migration: schema versioned; dual-read window (digest path preferred, mirror fallback) with `source=` observability; warn-mode semantics preserved; the four stored-flag consumer hooks (spec § 3.6) migrate with the flags — compat fields written until each lands; retired code paths carry a pointer to the superseding mechanism
- [x] Pass `/codex-review-fast` and `/precommit` (code plane), `/codex-review-doc` (doc plane) — this is a `hooks/` state-machine change: review at `thorough` (security/data-integrity adjacent: it produces the records the Stop gate trusts)
